# Decision log (working notes → ADRs)

The running log of the design conversations that produced the ADRs, kept so the *sequence* of reasoning stays visible. ADRs are the stable record; this file is the scratch-pad that shows the path.

## 2025–2026 (pre-repo) — problem shaping

- **Origin**: a public fact-checking resource for the NZ election with a sustainable model. Initially anchored on openfactcheck.com — research showed it to be an LLM-factuality *benchmark*, not a product pattern; LOKI and the FIRE/AVeriTeC ecosystem are the relevant state of the art.
- **Open-source pipelines with paid LLM services** is the pragmatic split (TUDA_MAI won AVeriTeC 2024 on GPT-4o; the open-weights-only 2025 winner scored 33%).
- **Full Fact licensing** examined in depth — viable but incompatible with open-scrutiny goals and NZ-specific flagship needs → ADR-0003.
- **Editorial staffing**: initial plan assumed 2–3 editors; rejected in favour of community-contested automated verdicts with mutation-on-validated-evidence — the project's defining design move.
- **Legal review** identified four exposures (s 199A, advertising characterisation, defamation, HDCA); the mutation freeze and claims-not-persons standard came directly out of it → ADR-0002.
- **Evaluation harness** elevated from nice-to-have to core trust asset when the no-editors model was chosen → ADR-0001, ADR-0010.
- **Statistical claims / cherry-picking** identified as the core risk class and value opportunity ("the main thing of value is the evidence politicians claim as the basis for their policy proposals") → ADR-0005 flagship.
- **Quick build for 2026**: 8-week plan cut (releases+Hansard first, LLM triage, FIRE-lite, 100-claim harness, simple contest form, freeze logic). ClaimBuster assessed and skipped at this scale.

## 2026-09-07 — repo created

- Repo initialised: `claimwatch-nz` (working name). Docs written: research review, architecture (4 mermaid diagrams), evaluation, legal-compliance, ADRs 0001–0008. ADR-0003 recorded as the first Decided outcome; ADR-0011 (providers) left Open — needed before pipeline code lands.
- **ADR-0006**: user-submitted URLs/text as a sixth ingestion lane — fetch-from-source rule (never verify from the submission's own rendering; re-retrieve server-side with archive fallbacks), submissions as queue-priority signal, HDCA guardrails shipping with the feature. Proactive social crawling stays deferred.
- **ADR-0006**: paywalled-content policy — no circumvention (TPM/ToS), paywalled content is a claim source not an evidence source, fair-dealing-bounded minimal quotation, claim-origin-paywalled labelling, commercial media-monitoring licences as the post-election option.
- **COVERAGE.md written**: every cited source live-probed. Findings: NZH politics feed silently empty; Scoop not machine-accessible; no party RSS anywhere; no bot challenges. Coverage established as a maintained property.
- **SOURCE-TAXONOMY.md written** (in place of a parked ingestion-architecture ADR): claim-source coverage matrix (anti-bias: ownership, geography, language/culture, format, audience dimensions; monthly audits; wire-dedupe rule) + evidence-authority map (T1–T6 tiers, precedence rule, per-domain authorities with denominator families for 14 policy domains).
- **Second probe round** (probe the not-yet-probed): Newsroom, The Post, The Press, Interest.co.nz have working feeds; ODT serves pages but no feed; Waatea JS-redirects; NZ First + Te Pāti Māori domains wrong/abandoned; 1News JS-rendered, no RSS.
- **SOURCE-TAXONOMY §1.2 revised**: the "Audience/political position" matrix dimension replaced with **"Audience/community served"** — observable descriptors instead of subjective leaning classifications (which would be attackable: "the fact-checkers labelled us X-leaning"). The audit's job is a gap question, answerable from audience descriptors. Verdict criteria remain party-blind (ADR-0002).
- **ADR-0013**: public proposal of claim sources and evidence authorities — two proposal types, one intake (GitHub issue templates pre-launch, site form post-launch), automated scope-check reusing COVERAGE tooling → public maintainer decision record with reasons; tier changes above T4 need subject-matter review. Proposers describe; the project classifies. Domain proposals not accepted. Proposals are consideration, not adoption; provenance labels for community-added entries.
- **MISINFO-TAXONOMY.md written + ADR-0005 revised**: Wardle & Derakhshan disorder types, the seven content types, DISARM/FIMI, and EU-2024 empirical distributions (decontextualisation 59.3% of verified disinformation; fabricated 32.9%; missing-context verdicts 23.4%; electoral integrity top topic at 20.5%). Architecture: technique-aware triage; false-context/provenance as its own mode; the stat engine as one mode of a multi-mode layer; **electoral-process claims the fastest lane** (s 199A interaction); manipulated media out of scope v1 with partner-referral path; imposter content as incident reporting.
- **ADR-0006**: **commentator watchlist** as sixth lane — prominent personalities commenting on politics, reach-based party-blind inclusion via decision record, per-commentator access paths; only factual claims *within* opinion are checked, never the opinion; register frozen during the regulated period.
- **ADR-0011**: selection principle **accuracy of assessment, paramount** — open-weights eligible wherever harness-validated; commercial frontier models welcome when affordable. Sept-2026 landscape: Claude Fable 5.1 recommended for verdict roles on calibration evidence; Gemini Flash / GPT-5.6 Luna / Claude Haiku class for bulk extraction; cross-family second-opinion pass as confidence signal; Brave Search API (Goggles domain-reranking maps onto authority tiers) + Serper fallback. Batch/non-realtime processing is a first-class cost lever.
- **ADR-0010 rewritten as two-layer evaluation**: Layer 1 — AVeriTeC's public dataset (4,568 claims, QA-evidence annotations, public eval script, reference scores 63%/33%) as the immediate benchmark for the generic loop from day one, removing the NZ-set dependency from early pipeline development. Layer 2 — the n=100 NZ-labelled set as the domain calibration set exercising the NZ source ecosystem (the thing AVeriTeC is blind to). Rationale: claim content doesn't need NZ specificity to measure verification skill, but the NZ source ecosystem dimension is real.

## 2026-09-12 — Source descriptors on the verdict page

- **Evidence source codes become plain-language labels, with the code confined to provenance.** The open-web loop writes a numeric source code onto every evidence row from the `TIER_GUIDANCE` prompt (`packages/pipeline/src/search/vetting.ts`); the verdict page published it as a bare `T1`/`T3` badge whose tooltip described a different set of meanings from `SOURCE-TAXONOMY.md` §2.1. Now: each row renders what the source *is* ("Official statistics", "Sector or advocacy body"), an inline "What these labels mean" key on the evidence card explains all levels in plain English, and the raw codes appear only in the provenance block for audit (SITE-MVP §2.2 rule 4, SIT-R4). Tripwire test pins the classifier's meaning — T2 = "Academic research".
- **Open:** the classifier's scale and `SOURCE-TAXONOMY.md` §2.1's evidence-authority ladder still disagree from T2 on (academic vs official administrative data). Public copy now follows the classifier because that is the code path that writes the stored value; reconciling the two schemes — or renaming one to stop the shared code space implying equivalence — is a pipeline prompt change with an L2 golden diff behind it, not yet scheduled.
- **Evidence list renders strongest source first, unclassified last.** The pack keeps the research order it was written in (append-only: the pack is the record); the page sorts a copy for display (`orderEvidenceBySourceQuality`, stable, ties keep the pack's order) and shows a "Not classified" chip on any row without a stored code rather than leaving it unexplained. Unclassified-last is deliberate: a row the adjudicator returned without a code is not the same thing as `evidence.ts`'s "series IS the finding" stat-grid row, so it must not be ranked as strong evidence. If stat-grid rows start landing as evidence items, this policy needs revisiting — or those rows need a distinct code, not a null.

## 2026-09-13 — The verdict page's provenance block becomes a dated trail

- **"How this verdict was made" is now a trail, not a paragraph.** The page said the same thing three times (a collapsed accordion, a "Checked … · How we check claims" metarow, and a dashed "produced by our automated pipeline …" line restating the accordion's own heading), and disclosed no dates at all. It is now four dated steps — the claim was made → we logged it and worked out what to check it against → what we compared it against → the verdict, a second pass on the reasoning, and publication — each with the sources it used, a plain "why it matters" line, and the facts that matter on the closed drawer so nothing needs a click to be understood (SITE-MVP §2.3/§2.5).
- **A claim's own date is now stored: `claim.spoken_at`.** The page previously rendered `verdict_version.created_at` (when the VERDICT was published) in the position that reads as the claim's date, so every page said the claim was made the day we checked it. Snapshot: `claim.spoken_at` (broadcast moment / item publication date), nullable and additive; the AVeriTeC slice run populates it from the benchmark's `claim_date`. Where it is absent the trail **omits** the "claim was made" step and the claim card shows no date — a missing date is not a date to guess at. `STORE_SCHEMA_VERSION` 0.2.0.
- **The technical record is always shown, and the copy was cut to per-stage facts (revision, same day).** The first version of this block put the four steps in collapsed drawers with the machine record behind a "show the technical record" checkbox; a day later the design was revised to a flat dated list with the audit line in each row. Two reasons: an audit record a reader has to ask for is one most readers never see, and the collapsed version carried roughly three times the text — an intro, bodies restating the method, and a "why it matters" line per step, most of it static across every claim. Now every line is either a fact about this claim (dates, counts, sources, the verdict) or, at most one per step, a single short sentence explaining the stage. Prompt roles are attributed to the step they belong to by name; **a role the site does not recognise is printed on the final step rather than dropped**, so provenance the page cannot interpret is still provenance the reader can see (HAR-R7).
- **Internal framing is not published as plain English.** The method line originally read "a number over a period → the official series" and, for claims with no recognised shape, "no routine shape → the open web" — the pipeline's own way of thinking, offered to a reader who has no reason to know we classify claims into shapes at all. It now states the check that happened ("Checked against the official figures for that number.", "Checked against whatever we could find online — our least reliable method, and the one most worth contesting."). Same rule as the register constraint, applied to framing as well as vocabulary: if a sentence only makes sense from inside the pipeline, it does not go on the page.
- **The audit vocabulary is defined where it is used.** The technical lines print values nobody outside the project can read (`method stat-grid`, `prompts citation-compare@1`, `verdict v1`, `source codes: T1`). A collapsed key under the trail — "What the technical record means" — now defines every label and value those lines can contain, including the five `method` values and the four verdict states (a FROZEN verdict is a fact the reader should meet on the page, not in a footnote). Same native-`<details>` pattern as the evidence card's source key; the key is in the server-rendered HTML and goes through the register check. Source rows keep their boxed formatting with the source's own finding: earlier in the same revision they were cut to title-plus-date on text-volume grounds, and restored because a reader scanning the trail should not have to go back up to the evidence card to learn what a source says.
- **Open:** per-step *times* are not stored. The store timestamps documents (claim, publication, evidence pack, verdict), not pipeline calls, so the four-drawer grouping is what keeps the trail's dates true; the second-pass paragraph is dated by position (before publication) rather than given a borrowed clock time. A per-call timeline would come from the `gen_ai.*` spans (ADR-0012) or new pack columns, and is not scheduled.

## 2026-09-13 — The audit line reads where it stands, and the key shrinks to the values

- **The labels on the audit lines are plain English; the values stay verbatim.** The lines used to print `pipeline 0.1.0-averitec-slice · verdict v1 · PUBLISHED · revisions 0 · prompts triage@1, adjudication@1 · models adjudication: claude-sonnet-5` and left the reader to hold thirteen definitions in their head while scrolling to a key below — a key that existed mostly to decode the *syntax* the page itself had chosen. They now carry their own labels (`ClaimWatch version 0.1.0 · verdict version 1 · state PUBLISHED · never revised · instructions triage@1, adjudication@1 · model adjudication: claude-sonnet-5`), and `check stat-grid` sits directly under the fact line that already says what that check was ("Checked against the official figures for that number."). The **values** are untouched: they are the join keys to the run file, the audit log and the harness export (AGENTS rule 4, STO-R10), and a gloss can drift from the store where a stored value cannot.
- **The key went from thirteen entries to four, and changed what kind of thing it is.** `TECHNICAL_RECORD_KEY` no longer defines labels the page spells out in English — it defines only the opaque *value* forms: `name@version`, the source-type codes, the four verdict states, and the `not recorded` sentinel. That is the shape the evidence card's own source key already has, and it means the key explains the values a reader meets rather than the vocabulary the page chose for itself. The `method` entry is gone rather than translated: the five method codes are now explained in place by the fact line above them. The heading changed with it — "What the technical record means" → **"What these values mean"** — so the surface doesn't promise a service it no longer performs.
- **The register exemption is now guarded instead of unguarded.** Moving the terms out of the key and into the *labels* would have walked the vocabulary straight through the banned-lexicon scan, which is exactly why the lines were exempt in the first place. So labels are drawn from `AUDIT_LABELS`, a reviewed allow-list, and `assertAuditLabelsKnown` runs on every rendered line: an unreviewed label fails the build. Values are deliberately not checked — a stored value is the record, so `instructions nli-audit@1` prints. This is the one place the project trades a scan for a list, and the list is small enough to read.
- **The existing bare-code check caught this revision's own copy.** The first draft of the new key entry was headed with a literal example code — scannable public copy, which SIT-R4 forbids. The render test's `bareSourceCode` token check failed the build, and the entry is now headed "source type codes" with the codes left in the exempt audit line. Worth recording as evidence the layered checks work: the register scan's word-shaped entries cannot see a bare code, and the token check is what stands in for them.
- **Open:** the store's fixture provenance still writes `promptVersions: { triage: "triage@1", adjudication: "adjudication@1" }` (`packages/store` `fullProvenance()`), and `adjudication` names a prompt that never existed — `ops/live-averitec-one.ts` records the slices used to write it. The site cannot attribute either name to a step, so both print on the final step by the HAR-R7 fallback, which is why the newest verdict pages show `instructions triage@1, adjudication@1` under "Decided and published" and `not recorded` under "Logged and sorted". Visible-on-purpose beats dropped, but the fixture and any legacy rows want the pipeline's real role names (`triage-typing`, `grid-materiality`, …), and legacy rows need a decision: republish, or map the old names as aliases.
